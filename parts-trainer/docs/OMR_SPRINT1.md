# Sprint 1: сканы низкого разрешения (ноябрь 2026)

Продолжение `docs/OMR_SPRINT0.md`. Цель — чтобы плохие сканы (≈150 dpi) читались, а результат на чистых PDF не менялся.

## Что ломало распознавание

Синтетические «сканы» с одним дефектом за раз (`tools/omr_eval/make_scan.py`: `res150`, `blur`, `noise`, `jpeg60`, `tilt2`,
`light` и пары `res150_*`), «Отче наш» (эталон) и 5 страниц Buus (нотоносцы):

| Дефект | Нотоносцы | Высоты «Отче наш» |
|---|---|---|
| нет (чистый PDF) | 100 % | 97,1 % |
| только 150 dpi / шум σ12 / JPEG q60 / неровная яркость | 100 % | 97,1 % |
| размытие (σ 1,5 px) | Фёдоров 14/18 | **36,4 %** |
| 150 dpi + размытие | Buus 30/60, Фёдоров 15/18 | **47,4 %** |
| наклон до 2° | 100 % | 87,9 % |

Главная причина — **размытие**: линейки становятся бледно-серыми (самая тёмная точка ≈ 186 из 255 при пороге ≈ 204),
быстрый поиск их теряет, а нотоносцы, распавшиеся на части системы, путают партии. Разрешение, шум и JPEG сами по себе
не мешают. Проверка на Python: нерезкая маска (σ 2, сила 2) на странице шириной 1920 возвращает 18/18 и 97,1 %.

## Что сделано

1. **Резкость краёв** страницы (`ImageOps.edgeSharpness`: 90-й процентиль перепадов яркости по вертикали на краях штрихов):
   PDF — 255, сканы 300 dpi — 130–160, 200 dpi — 75–100, 150 dpi и размытые — 43–61. Ниже 140 страница получает
   **нерезкую маску** (`ImageOps.unsharp`) перед CLAHE. Чистые страницы не меняются (токены «Отче наш» и Buus — прежние).
2. **Никогда не хуже, чем было**: у размытой страницы линейки ищутся и с резкостью, и без, берётся вариант с бо́льшим числом
   нотоносцев.
3. **SegNet заполняет пропуск**: раньше нейросеть включалась, только если быстрый поиск не нашёл ничего. Теперь — и когда
   внутри системы пропуск между строками больше 1,75 обычного; её ответ берётся, только если он содержит все уже
   найденные строки и добавляет новые. На чистых и реальных страницах срабатывает лишь там, где строка правда пропущена.

Время: на чистых страницах +3–5 мс (только оценка резкости). На размытых — около +0,6–0,8 с на страницу (маска ≈ 0,3 с,
второй CLAHE и второй поиск линеек ≈ 0,3–0,5 с) при чтении строк 2–3 с; SegNet (≈ 3 с) — только на страницах с пропуском.

## Осталось

* Наклон 2° у одной страницы «Отче наш»: строки найдены, но система делится неверно (у края синтетической страницы
  черта системы частично уходит за кадр) — проверить на реальных наклонных сканах.
* Плотная 12-голосная страница с волнистыми линиями (s5-02/03): 10 из 12; SegNet там тоже не находит остальные.
* Скорость: размытые страницы — маску можно считать быстрее (box-приближение Гаусса) при необходимости.
